# 動的モードのテーブル配置対応検討メモ (2025-11-24)

## 背景
- 動的モードで `prepare` → `compose` → `gen` を実行した際、`generate_ready.json` ではテーブル構造が保持されるものの、レンダリングされた PPTX では既存プレースホルダーではなく、新規に生成されたシェイプへ表が配置された。
- 静的モードでは Blueprint の slot 情報 (`content_type") を基にテーブルが既存プレースホルダーへ収まっているため、この差分を解消したい。

## 課題
- Executive Summary レイアウトなど、テンプレート側に表専用のプレースホルダーが無い場合、`mapping` 時点で表をどのアンカーへ割り当てるか判断できず、レンダリングステップが新規シェイプを生成してしまう。
- 動的パイプラインでは `elements["table"]` のまま保持され、アンカー名への変換が行われていない。

## 対応方針（ディスカッション合意）
1. **ヒューリスティックを優先**
   - レイアウトの `media_hint` やプレースホルダーの命名 (`Body Left`, `Body Right`, `Notes` など) を利用して、テーブルを許容する枠に自動で割り当てるルールを実装する。
   - 典型的なレイアウト（Executive Summary など）はこのルールで対応可能。
2. **補助設定での上書き**
   - ヒューリスティックで決められないケースは、レイアウト別の override 設定（例: mapping 用の設定ファイル）でアンカーを明示指定できるようにする。
3. **LLM は最後の手段**
   - どうしても判断できない残りのケースのみ LLM に委ねるハイブリッド構成とし、コストと揺らぎを最小化する。
4. **テーブル以外も同様に拡張可能な構造**
   - 今回の対応はテーブルを起点とするが、画像やチャートなど他メディアでも同じ仕組みで割当ルールを拡張できるよう実装を整理する。

## 制約・懸念事項
- Executive Summary のように複数プレースホルダーがある場合、どの枠に割り当てるかの優先順位づけが必要。ヒューリスティック設計を誤ると既存のテキスト配置が崩れる可能性がある。
- ユーザーの既存ドキュメントに合わせた柔軟性を確保するため、設定ベースの override を準備しておく必要がある。
- LLM を利用する場合でも、同じ入力で同じ結果が得られること（揺らぎ対策）が求められるため、呼び出しフローやキャッシュ戦略を検討する必要がある。

## 想定修正ファイル
- `src/pptx_generator/pipeline/draft_structuring.py`: `_merge_slide_elements` もしくは `mapping` の直前で表をアンカーに紐付ける処理を追加。
- `src/pptx_generator/pipeline/mapping.py`（必要に応じて）: ヒューリスティックの実装や override 設定の適用ロジックを追加。
- `config/` 配下（予定）: レイアウト別のプレースホルダー指定を記述する設定ファイルを追加する可能性あり。
- `tests/test_cli_integration.py` / `tests/test_draft_structuring_step.py` など: テーブルが既存プレースホルダーへ割り当てられることを確認する統合テスト・単体テストを追加。
