# コンテキスト設計ポリシー

## 目的と適用範囲
- coding agent を利用した開発作業において、LLM へ渡すコンテキスト量と粒度を制御し、コスト増加やハルシネーションを抑制する。
- README / AGENTS / `docs/` 配下のドキュメント、および ToDo・Plan の記述方法に本ポリシーを適用する。
- `docs/notes/20250214-context-engineering-hand-off.md` を出発点とし、必要に応じて本ポリシーを更新する。

## 基本原則
1. **Upfront 情報はサマリに限定する**  
   - README・AGENTS など upfront で参照される文書には、ゴール・主要入力・主要出力・制約・参照先リンクなど要約情報のみを掲載する。詳細は専用ドキュメントへ委譲する。
2. **オンデマンド参照を前提に設計する**  
   - 必要な情報は `rg` 等で検索し、該当するドキュメント・コードのみをコンテキストへ投入する。Plan や ToDo では参照リンクを明示し、全文貼付を避ける。
3. **コンテキストを階層構造で管理する**  
   - 「プロジェクト全体の原則」「ステージ別要件・設計」「タスクローカル情報」「コード／スキーマ」の四層に整理し、読み順と更新責務を区別する。
4. **タスク単位で情報を分離する**  
   - ToDo や Plan、ノートにタスク固有のメモを残し、他タスクと混在させない。必要に応じて `docs/notes/` にタスク専用ファイルを設ける。

## ドキュメント階層と参照順
- **レベル1: プロジェクト原則**  
  `AGENTS.md`, `CONTRIBUTING.md`, `docs/policies/*.md`。リポジトリ共通ルールを記載し、最初に参照する。
- **レベル2: 要件・設計**  
  `docs/requirements/`, `docs/design/`。ステージや機能ごとの仕様と設計を記載する。レベル1を前提とした詳細を提供。
- **レベル3: 運用手順**  
  `docs/runbooks/`, `docs/policies/task-management.md`。実務手順やフォールバックをまとめる。参照時はレベル1・2へのリンクを保持する。
- **レベル4: タスク・調査メモ**  
  `docs/todo/`, `docs/notes/`, Issue / PR。タスク固有の記録。Plan 承認後は ToDo に参照リンクを必ず記載する。

各ドキュメントでは、上位階層へのリンクと役割を明確に記し、詳細は下位ドキュメントへ委譲する。

## Upfront 文書の記述ガイド
- README / AGENTS / `docs/README.md` など最初に参照される文書は、概要・前提・参照先リンクといったサマリ情報のみを記載し、詳細手順は下位ドキュメントへ誘導する。
- Runbook や ToDo は、対象タスクの目的と完了条件を簡潔に示し、必要なチェックリストや参照資料の位置を明記する。
- Upfront 文書から詳細へ移る導線（リンク、ファイルパス、検索キーワードなど）を必ず提示し、全文転記は避ける。

## 参照方法とツール利用ルール
- `rg`, `fd`, `uv run pptx --help` など軽量ツールを優先し、必要な情報のみ抽出する。全ファイルの貼付や大規模コピーは避ける。
- 利用可能な検索手段を Plan に明記し、Plan 承認後にのみドキュメントを書き換える。
- コンテキストとして読み込んだ資料を PR やノートに引用する際は、必要部分を抜粋・要約し、原文リンクを併記する。

## 運用と更新
- 本ポリシーに従うドキュメント改訂を行う場合、変更理由と参照範囲を ToDo の「ドキュメント更新」メモに記録する。
- 新たなカテゴリやテンプレートを追加する際は、本ポリシーの階層と整合するか確認し、必要ならセクションを増補する。
- 半期ごとに `docs/notes/` へレビュー結果を記録し、ポリシーの改善点を洗い出す。

## ロールバック
- 本ポリシーに基づく変更で運用上の問題が発生した場合は、関連コミットを `git revert` し、影響範囲と判断理由を `docs/notes/` に追記する。
- 元に戻した後、改善案を別ブランチで再検討する。
