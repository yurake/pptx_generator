# ポリシードキュメント索引

## 目的
- `docs/policies/` 配下で運用ルールを横断的に整理し、どの文書をどの順番で参照すればよいかを明確にする。
- README や AGENTS のサマリから詳細へ進む導線を補完し、タスクごとに必要なポリシーを素早く確認できる状態を保つ。

## 更新手順
1. ポリシーを新規追加・改訂した場合は、本索引に概要と参照リンクを追記する。
2. 参照先が増減した際は `docs/README.md` や関連ガイドからのリンクも見直し、重複や齟齬がないか確認する。
3. ポリシー間で前提が変わった場合は、影響範囲の文書（ToDo、設計／要件ドキュメント、Runbook など）へも更新内容を伝搬させる。

## 参照順
1. **コンテキスト設計**: 情報の階層化と参照範囲の原則を理解する。
2. **タスク管理**: Approval-First Development Policy や ToDo 運用を確認する。
3. **設定・テンプレ管理**: CLI が参照する設定やテンプレートを変更する際のルールを確認する。
4. **GitHub ラベル運用**: Issue/PR ラベル体系を更新する場合のみ参照する。

## ドキュメント一覧
- `context-engineering.md`  
  - Upfront ドキュメントをサマリ化し、必要な情報をオンデマンドで取得するためのコンテキスト設計ポリシー。ドキュメント階層と参照方法、更新時の原則を定義する。
- `task-management.md`  
  - Approval-First Development Policy を中心としたタスク運用ガイド。Plan 提示から ToDo 管理、PR 作成、ロードマップ更新までの手順とチェック項目をまとめる。
- `config-and-templates.md`  
  - `config/` 配下の設定や `.pptx` テンプレートを変更する際の手順。バリデーション方法、命名規則、成果物の配置ルールを記載する。
- `github-label-governance.md`  
  - GitHub ラベル体系の整備と自動付与ワークフローの方針。新規ラベル追加や再分類を行う際のチェックリストを提供する。

## 追加ポリシー作成時のチェックリスト
- 目的・適用範囲・更新責務を明記し、既存ポリシーと重複しない役割を説明したか。
- 必要な関連ドキュメント（要件・設計・Runbook・ToDo）への導線を整理したか。
- 本索引と `docs/README.md` に新規ポリシーへのリンクを追加したか。
- Plan／ToDo のメモ欄に変更理由や参照リンクを記録し、承認履歴を残したか。
